# 터틀넥 코어 계약 v1.0

상태: 구현 고정 계약
기준일: 2026-11-16 Asia/Seoul

이 문서는 Moodle·Canvas·로컬 학습 흐름을 고도화할 때 지켜야 하는 공통 경계다.
기능을 추가할 때 이 계약과 다르면 먼저 계약을 바꾸고, 그 다음 코드를 바꾼다.
실계정 검증이 없다는 이유로 코드가 구현된 것으로 가장하지 않으며, 구현 상태와 검증 상태를 따로 기록한다.

## 1. 제품 범위

터틀넥의 핵심 흐름은 다음이다.

```text
사용자 요청
  → 로컬 실행기
  → 학교 Provider
  → 정규화된 로컬 데이터
  → 자료·학습·시험·제출 기능
```

포함한다.

- 표준 Moodle과 학교별 Moodle 모듈의 읽기 수집
- Canvas 읽기 API 수집
- 과목·과제·공지·강의·자료의 로컬 저장과 재사용
- 사용자가 선택한 원본 파일의 로컬 보관
- 자료 기반 학습·문제은행·웹 시험
- 관찰된 Moodle 제출 양식의 계획·승인·제출·재확인

포함하지 않는다.

- 출석·시청시간을 위조하거나 동영상 재생을 대신하는 기능
- 다운로드 금지·접근 제한 우회
- 사용자의 명시적 승인 없는 원격 POST·업로드·삭제·강좌 수정
- Canvas 쓰기 기능. 별도 계약과 실환경 검증 전까지 읽기 전용이다.

## 2. 계층과 책임

| 계층 | 책임 | 금지 사항 |
| --- | --- | --- |
| `scripts/` | 로그인·동기화·제출 같은 실행 흐름 조립 | HTML 파싱 규칙을 여러 스크립트에 복제 |
| `providers/` | 학교별 인증·HTTP·응답 파싱·정규화 | 학습 문항 생성·사용자 대화 처리 |
| `storage/` | SQLite·파일·동기화 시각 저장 | 비밀번호·쿠키·API 토큰 저장 |
| `features/` | 로컬 학습·시험·과제·상태 계산 | 학교별 엔드포인트 직접 호출 |
| AI 호스트 | 요약·문항·채점·번역 등 의미 작업 | 학교 서버 직접 접근·자격증명 읽기 |
| 보조 앱/브라우저 | 로그인 입력·시험 화면·사용자 확인 표시 | 백그라운드 크롤러 역할 |

공통 Provider는 `Course`, `Assignment`, `Notice`, `Lecture`, `Resource`를 반환한다.
학교마다 없는 자료는 빈 목록이나 `UNKNOWN`으로 반환하며 추측해서 채우지 않는다.

## 3. 정규 데이터 계약

모든 레코드는 `source`를 가진다. 허용 값은 `tls`, `moodle`, `canvas`, `manual` 및 명시된 외부 자료 종류다.

- ID는 내부 안정 ID이며, 외부 숫자 ID를 그대로 전역 키로 사용하지 않는다.
- `externalId`는 Provider 내부에서만 해석한다. 다른 학교의 숫자 ID와 비교하지 않는다.
- `Course`: `id`, `externalId`, `name`, `source`, 선택 `professor`, `semester`
- `Assignment`: `id`, `externalId`, `courseId`, `title`, `description`, `dueAt`, `submissionStatus`, `source`
- `Lecture`: `id`, `externalId`, `courseId`, `title`, `durationSeconds`, `watchedSeconds`, `watchProgress`, `completed`, `source`
- `Notice`: `id`, `externalId`, `courseId`, `title`, `content`, `publishedAt`, `source`
- `Resource`: `id`, `externalId`, `courseId`, `title`, `fileName`, `extension`, `mimeType`, `remotePath`, `localPath`, `downloadStatus`, `downloadReason`, `source`

상태 규칙:

- 제출: `NOT_SUBMITTED`, `SUBMITTED`, `LATE`, `UNKNOWN`
- `UNKNOWN`은 미제출로 세지 않는다.
- 강의 `completed`가 시청률보다 우선한다.
- 최신 확인 실패 시 이전 기록을 최신 데이터처럼 보고하지 않는다.

## 4. 계정·비밀값 경계

사이트와 계정 별칭은 하나의 프로필로 취급한다.

```text
사이트 + 별칭
  → OS 보호 저장소 항목
  → 프로필별 SQLite
  → 프로필별 files/
```

- macOS: Keychain
- Windows: 보호 저장소/DPAPI
- 비밀번호·쿠키·세션·Bearer 토큰은 DB·로그·AI 입력·일반 JSON에 넣지 않는다.
- 같은 비밀번호를 다른 사이트에서 쓰는 것은 사용자가 명시적으로 연결한 경우에만 참조한다.
- Canvas 토큰은 TLS 비밀번호와 별도 서비스 이름으로 보관한다.
- AI가 로컬 명령을 실행할 수 있는 환경은 완전한 비밀 격리가 아니다. 이 한계를 숨기지 않는다.

## 5. 동기화와 부하 계약

동기화는 범위별로 분리한다.

| 범위 | 기본 재사용 기한 | 원본 바이트 |
| --- | ---: | --- |
| 과목·활동 목록 | 5분 | 받지 않음 |
| 과제·시청 상태 | 15분 | 받지 않음 |
| 공지 본문 | 6시간 | 받지 않음 |
| 자료 메타데이터·권한 | 24시간 | 받지 않음 |
| 선택한 원본 파일 | 사용자 요청 시 | 해당 파일만 |

필수 규칙:

- `metadata-only`는 파일 바이트를 받지 않는다.
- `resource-only`는 지정 자료와 그 자료가 있는 수강 강좌만 읽는다.
- 새 자료 ID가 없다는 이유로 전체 학사 동기화를 시작하지 않는다.
- 같은 DB·프로필의 동시 동기화는 하나만 실행한다.
- 일반 병렬성은 최대 2개 세션이며, 세션 시작 간격은 0.25초 이상이다.
- GET과 명시된 읽기 전용 요청만 제한된 재시도를 허용한다.
- `Retry-After`와 서버 쿨다운을 우회하지 않는다.
- 원본 파일·동영상·음원·전사는 고부하 기능으로 분류하고 자동 일괄 실행하지 않는다.
- 허용된 원본 파일과 미디어는 메모리에 전체를 올리지 않고 계정별 임시 파일로 스트리밍한 뒤 검증·원자적으로 저장한다.
- 다운로드 제한·403·뷰어 전용 응답은 원본 바이트를 받지 않으며, 별도 허가도 특정 자료와 실제 서버 허용 상태를 다시 확인한 뒤에만 적용한다.
- Canvas도 최종적으로 같은 범위별 캐시 계약을 구현해야 한다. 현재는 API 목록 수집과 프로필 저장까지만 구현된 상태다.

### 모바일 앱·푸시 경계

- 코스모스/Moodle 모바일 앱의 사설 API, 앱 세션, 기기 푸시 토큰, AirNotifier 자격증명을 추출하거나 재사용하지 않는다.
- 공지·과제·피드백 알림은 학교가 공식 Moodle Message API·모바일 알림·AirNotifier 연동을 제공할 때만 그 경로를 사용한다. 개인 클라이언트가 임의의 푸시를 주입하지 않는다.
- 공식 푸시 연동이 확인되지 않으면 변경사항을 로컬 DB에 저장하고 보조 앱의 macOS/Windows 알림으로만 안내한다.
- 앱의 상태 변경 훅을 확인할 때도 공개 문서·학교가 발급한 Web Service·비밀값 없는 fixture만 사용한다. 앱 바이너리 분석, 사설 엔드포인트 추측, 세션·토큰 재사용은 지원 범위가 아니다.
- 터틀넥이 원격에서 과제를 제출하거나 공지를 등록했다고 해서 모바일 푸시가 발생한다고 가정하지 않는다. 서버가 해당 이벤트와 알림을 공식적으로 생성하는지 재조회로 확인해야 한다.

## 6. 원격 쓰기 계약

모든 원격 변경은 다음 세 단계를 거친다.

```text
inspect → plan → apply + 사용자 확인 → re-read verify
```

- `inspect`: 실제 같은 출처의 양식·주소·필드를 확인한다.
- `plan`: 대상·파일·변경 내용을 사용자에게 보여준다.
- `apply`: 명시적인 확인 문구가 있을 때만 POST/업로드한다.
- `verify`: 같은 화면 또는 공식 API를 다시 읽어 실제 결과를 확인한다.
- 확인되지 않은 결과는 성공으로 반환하지 않는다.
- 이미 제출된 과제는 기본적으로 재전송하지 않는다.
- 파일 업로드 성공과 최종 제출 성공은 별도 상태로 보관한다.
- Canvas 제출·업로드·강좌 수정은 이 버전에서 지원하지 않는다.

## 7. 자료 제한 계약

- 화면·공지·응답에서 다운로드 금지가 명시되면 바이트를 받지 않는다.
- 서버가 403을 반환하면 금지 상태로 기록한다.
- 허가 예외는 특정 자료·담당자·사용자의 실제 허가 문장에만 적용한다.
- 허가가 과목 전체나 이후 버전으로 자동 확장되지 않는다.
- 숨은 URL·스크립트·추측한 문서 ID를 사용하지 않는다.

## 8. Canvas 검증 등급

Canvas 실계정이 없으면 다음 이상을 주장하지 않는다.

| 등급 | 근거 | 표시 |
| --- | --- | --- |
| C0 | 코드 정적 검사 | 구현 초안 |
| C1 | fixture·모의 API·페이지네이션·비밀값 검사 | API 계약 검증 |
| C2 | 사용자가 제공한 비밀 제거 HAR/응답 | 특정 Canvas 환경 확인 |
| C3 | 학교 승인 테스트 계정의 읽기 전용 연결 | 해당 학교 읽기 지원 |

현재 Canvas는 C1이다. C1을 “대학 전체에서 동작” 또는 “실제 Canvas 연결 완료”로 표현하지 않는다.
공개 목록에 있는 학교도 로그인 주소·SSO·Canvas 설정이 다를 수 있으므로 목록은 후보 탐색용으로만 사용한다.

## 9. 코스모스 기관 레지스트리

코스모스 공개 기관 목록은 `skills/university-agent/data/coursemos_institutions.json`에 저장한다.
목록의 각 항목은 다음 흐름으로 사용한다.

```text
공개 기관 목록
  → 학교 LMS 주소 확인
  → 사용자 직접 로그인
  → 읽기 전용 Moodle/Canvas 감지
  → 비밀값 없는 마이그레이션 리포트
  → 학교별 모듈 제안
```

공개 목록의 기준일과 출처를 함께 보존하며, 목록만으로 지원을 보장하지 않는다.
`/local/ubeclass`, `/local/ubion`, KKU 전용 동영상·문서 경로를 다른 학교에 추측해서 보내지 않는다.

## 10. 변경 관리

- 데이터 필드 변경은 이 문서와 `references/provider-contract.md`를 함께 갱신한다.
- 기존 DB를 깨뜨리는 변경은 마이그레이션 번호를 추가한다.
- Provider 변경은 fixture·실패 보존·비밀값 제거 테스트를 함께 추가한다.
- 부하 개선은 요청 수·응답 본문량·경과 시간·실패 수를 같은 조건에서 비교한다.
- 모의 측정은 실서버 부하 감소로 표현하지 않는다.
- 계약 변경 후 전체 회귀·macOS/Windows 설치·가능한 학교 읽기 테스트를 배포 마지막 단계에서 실행한다.
