# 후속 최적화 1·2단계 보고 메모

2026-11-06 · 로컬 변경 · 푸시하지 않음

**입력 중복을 제거했지만 실제 생성 시간 개선은 아직 입증하지 못했다.**

- 추출 CLI 응답을 `hostOnly.requests`로 통일해 첫 원문/설명의 중복을 없앴다.
- 기존 compact JSON을 파일로 직접 제출하도록 안내·통합 검사했다. 시험마다 Python
  작성 스크립트를 만드는 과정이 필요하지 않다.
- 직접 Python 호출, 원문·이미지 참조, 인용·권한 검사와 최종 검토는 유지했다.

| 확인 내용 | 결과 |
| --- | ---: |
| 같은 실제 Java2 요청의 반환 크기 | 42,891 → 21,715바이트, 약 49.37% 감소 |
| 합성 본문 1/2요청 반환 크기 | 각각 49.59% / 42.73% 감소 |
| 실제 Java2 30문항·HTTP 준비 | **81.2초** |
| 이전 관측 | 69.9초, 조건이 달라 인과적 단축률 계산 불가 |
| 전체 회귀 | **395개 통과**, 환경 의존 1개 건너뜀 |

이번 실행은 실제 CLI 프로세스·웹 실행기를 사용했고 문항과 출력량도 달랐다. 관측값은
이전보다 길었으며 **60초 목표 미달**이다. 바이트 감소를 생성 속도 개선으로 주장하지 않는다.
다음은 동일 출력 조건의 비교, 재생성 시 부족분만 추가하는 캐시 개선 순서다.

설치본 자동 갱신·부족분 캐시 개편·호스트 병렬 생성은 이번에 하지 않았다.
루트 SOURCE를 읽던 외부 CLI 소비자는 v2 requests 방식으로 이행해야 한다.
