# 학습·문제 생성 시간 제한 대응 계획

## 확인된 실제 실패 유형

시험 공부 자료 정리 채팅 기록에서 다음 문제가 확인됐다.

| 흐름 | 관측 시간 | 판단 |
| --- | ---: | --- |
| TLS 퀴즈 등록·문항 교체 | 약 66분 | 문항별 조작과 잘못 선택한 등록 경로가 반복됨 |
| TLS 자료 2개 다운로드 | 약 28분 | 전체 동기화와 자료별 권한·뷰어 재검증이 먼저 실행됨 |
| 자율강좌 업데이트 | 약 13분 | 로그인·권한·강좌 구조 확인이 한 작업에 묶임 |
| 강의 전사 | 약 27분 | 음원 변환 실패 후 대체 변환 경로를 순차 시도함 |
| 모의고사 생성 | 약 39분 | 여러 과목 자료와 문제 유형을 한 번에 처리함 |

별도로 Codex 사용량 한도에 걸린 실패도 있었으며, 이는 TLS나 로컬 코드의 시간 초과와 구분한다.

## 갱신된 목표

전체 작업 완료 시간을 먼저 줄이는 것이 아니라, 사용자가 1~2분 안에 첫 결과를 받고 작업이 중단돼도 이어갈 수 있게 한다.

1. 첫 응답 예산: 자료 선택·캐시 확인·진행 상태 반환을 120초 이내로 제한한다.
2. 긴 작업 분리: 자료 읽기, AI 분석, 후보 검토, 최종 조립, TLS 반영을 별도 단계로 저장한다.
3. 재개 보장: 각 단계의 입력·결과·실패 원인을 로컬에 저장하고 같은 단계는 재실행하지 않는다.
4. 배치 상한: AI 분석은 현재처럼 작은 묶음으로 보내며, 한 채팅 턴에서 전체 과목·전체 문항을 끝내려 하지 않는다.
5. TLS 쓰기 단일화: XML/백업 기반 일괄 등록을 우선하고 문항별 등록은 관찰된 양식이 꼭 필요한 경우에만 사용한다.
6. 명확한 중단: 작업이 예산을 넘으면 성공처럼 말하지 않고, 완료 수·남은 수·다음 재개 지점을 반환한다.
7. 검증 분리: 로컬 회귀 통과, 실제 TLS 왕복, AI 사용량 한도는 각각 별도 결과로 기록한다.

## 작업 순서

- [ ] 학습 파이프라인의 첫 응답에서 동기식 전체 자료 준비 제거 또는 분할
- [ ] 단계별 시간 예산과 `paused/failed/resumable` 상태 추가
- [ ] TLS 퀴즈 등록을 일괄 경로 우선으로 고정하고 중복·오류 시 원자적 보존
- [ ] 다운로드·전사·문제 생성의 진행률과 재개 지점 통합
- [ ] 소량·대량 fixture 벤치마크에 첫 결과 시간과 중단 후 재개 시간을 추가
- [ ] 실제 TLS 검증과 OS별 번들 검증은 코드 검증과 분리해 별도 보고

## 현재 코드와의 관계

현재 `study_pipeline`은 캐시, 2개 단위 분석 배치, 중간 저장, 후보 재분석 방지를 이미 제공한다. 하지만 초기 자료 준비와 일부 메타데이터 조회가 동기식이므로 첫 응답 지연 가능성이 남아 있다. 이 문서는 해당 지연을 다음 우선 작업으로 승격한다.
