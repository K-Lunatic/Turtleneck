# Rust 부분 채택 보고 메모

작성일: 2026-11-06 · `experiment/rust-core-refactor` · 푸시하지 않음

**활동·섹션 개요 파서는 명시적 실험 실행 경로에 부분 채택했다.** 전체 20% 개선 대신
모듈 자체 개선·동등성·관련 전체 흐름의 비악화를 기준으로 바꿨다. 기본 Python 실행은 유지한다.

| 비교 | Python → Rust 경로 | 결정 |
| --- | ---: | --- |
| 활동 1,000개 | 13.310→2.641 ms | **80.16% 단축, 채택** |
| 섹션 개요 1,000개 | 28.296→3.068 ms | **89.16% 단축, 채택** |
| 실제 9과목 전체 지문 계산 | 79.768→27.013 ms | **66.14% 단축**, 결과 일치 |
| 전체 메타데이터 재현 | 1,144.236→1,136.586 ms | 큰 전체 가속 주장은 안 함, 비악화 확인 |
| 개념 1,000개 점수·정렬 | 1.295→4.134 ms | JSON/FFI 비용 때문에 **미채택** |
| DB 포함 개념 1,000개 조회 | 4.838→7.415 ms | **53.26% 느려짐** |

동일 입력으로 30쌍씩 비교했고 변환·호출·복구 비용을 포함했다. 개념 계산은 저장 이력의
우선순위 점수와 정렬이며, AI 의미 분류/문항 생성 자체를 Rust로 바꾼 것은 아니다.

**내부 웹도 실제 API로 측정했다.** 6문항 시험 상태 API는 1클라이언트 **2.242→2.176ms**,
4개 동시 요청 완료 배치는 **46.613→46.248ms**였다. 해당 요청의 HTML 파서 호출은 0회라
이번 파서 전환의 효과로 해석하지 않는다. Rust 웹 서버 포팅은 하지 않았으며, 프로파일에
보인 SQLite·상태 저장·반복 I/O를 다음 웹 후보로 남겼다. 토큰/Origin 검사는 유지했다.

기존 회귀 **382개**, 실험 Python **27개**, Rust **6개** 통과. 환경 의존 검사 2개는 건너뛰었다.
원본 DB·학교 데이터는 바꾸지 않았다. 승인 모듈만 활성화하는 `experiments/rust-core/run.py`와
부분 판정 도구를 구성했으며, DLL이 없거나 예전 ABI이면 Python으로 돌아간다.

다른 OS·배포 번들·두 모듈 조합의 최대 메모리는 미검증이다. 코드·판정·측정은 실험 브랜치에
보관하고 운영 `turtleneck`이나 원격 저장소에는 반영하지 않는다.
