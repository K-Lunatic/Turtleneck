# 자동 실행과 호스트 연동

터틀넥은 대화가 시작되거나 프롬프트가 제출될 때마다 학교 사이트에 접속하지 않습니다. 로그인과 동기화가
필요한 작업에서만 로컬 실행기가 동작하며, 이미 확인한 결과는 로컬 캐시를 사용합니다.

## 현재 자동 동작

| 시점 | 동작 | 네트워크 요청 |
| --- | --- | --- |
| 첫 호출 | 로컬 설정과 저장 상태 확인 | 없음 |
| 학교 자료 요청 | 저장된 세션 확인 후 필요한 범위만 동기화 | 필요할 때만 |
| 매일 예약 시각 | TLS 과제·강의·공지 상태 확인 | 컴퓨터가 켜져 있을 때만 |
| 시험·학습 요청 | 로컬 자료와 분석 기록 재사용 | 새 자료가 필요할 때만 |
| ChatGPT 모바일 요청 | 사용자가 켜 둔 로컬 게이트웨이에 전달 | 게이트웨이와 터널이 켜져 있을 때만 |

## 라이프사이클 훅

현재 Codex·Claude Code·Gemini CLI·Antigravity CLI용 패키지는 `SessionStart`나 `UserPromptSubmit` 같은
라이프사이클 훅을 등록하지 않습니다. 따라서 터틀넥이 사용자의 모든 프롬프트를 가로채거나, 대화가 시작될
때 로그인 창을 자동으로 열거나, 매번 전체 동기화를 시작하지 않습니다.

이것은 빠진 기능이 아니라 의도한 안전장치입니다.

- 학교 계정과 세션을 대화 입력과 분리합니다.
- 사용자가 요청하지 않은 서버 요청을 만들지 않습니다.
- 만료된 세션을 반복해서 재인증하지 않습니다.
- 훅을 지원하지 않는 호스트에서도 같은 동작을 유지합니다.

호스트가 훅을 지원하더라도 터틀넥의 기본 사용 흐름은 동일합니다. 자동화가 필요한 경우에는 로컬 예약
동기화(`setup_turtleneck.py --watch-install`)를 사용하고, 즉시 확인이 필요할 때만 터틀넥을 호출하세요.

## 호스트별 차이

- Codex·Claude Code·Gemini CLI·Antigravity CLI: 스킬 또는 플러그인을 명시적으로 호출합니다.
- 일반 ChatGPT 웹 대화: 로컬 보호 저장소에 직접 접근할 수 없습니다. 사용자의 컴퓨터에서 Actions 게이트웨이를
  실행한 경우에만 제한된 조회와 시험 화면 연결이 가능합니다.
- 모바일: 독립 실행이 아니며, 사용자의 컴퓨터와 게이트웨이가 온라인이어야 합니다.

훅이 추가되면 학교 서버 요청, 자격증명 접근, 실패 시 재시도 정책을 먼저 검토하고 이 문서와 테스트를 함께
갱신합니다.

## 플러그인 계정 연결과 TLS 로그인

ChatGPT에서 보이는 Notion의 `연결된 계정` 화면은 제공자가 OAuth 연결을 지원할 때 사용하는 계정 연결 UI입니다.
플러그인이 임의의 사이트 아이디와 비밀번호를 그 화면에 직접 저장하거나 읽는 기능은 아닙니다.

현재 TLS는 표준 OAuth 제공자가 아니고 학교 로그인 세션과 쿠키를 사용하므로, 이 UI를 TLS 계정에 그대로 연결할
수 없습니다. 터틀넥은 다음 경로를 사용합니다.

1. 사용자가 로컬 로그인 화면에서 TLS 계정을 입력합니다.
2. 로그인 성공을 확인한 뒤에만 자격증명을 운영체제 보호 저장소에 기록합니다.
3. AI 대화, 로그, 일반 DB에는 비밀번호·쿠키를 넣지 않습니다.
4. 세션이 만료되면 실패 이유를 표시하고, 필요한 경우에만 다시 로그인합니다.

TLS 운영자가 OAuth 또는 공식 API를 제공하는 경우에는 별도 provider 모듈로 OAuth 연결을 추가할 수 있습니다.
그때도 임의의 비밀번호 수집 폼으로 대체하지 않고, 승인 범위와 갱신 토큰을 검토한 뒤 연결합니다.
