# 실기기 배포 검증 체크리스트

GitHub Actions는 번들 빌드와 호스트 Python·Git을 숨긴 실행까지 확인한다. 아래 항목은 실제 사용자의 깨끗한 기기에서 한 번만 수행한다.

## 공통 준비

- 공식 GitHub Release의 번들과 `.sha256` 파일만 사용한다.
- 체크섬이 일치하는지 확인한다.
- 테스트 계정 또는 테스트 강좌를 사용하고, 비밀번호·쿠키·원본 자료를 화면 녹화와 로그에 남기지 않는다.
- 검증 전후의 `~/.university-agent`(Windows는 `%USERPROFILE%\\.university-agent`) 목록만 기록하고 파일 내용은 공유하지 않는다.

## macOS

1. Python과 Git이 없는 새 사용자 계정에서 번들의 `turtleneck --version`과 `--help`를 실행한다.
2. 첫 실행의 Gatekeeper 안내가 공식 체크섬 확인 후에만 우회되도록 확인한다.
3. 보조 앱 `--status`가 동작하고 상태 출력에 비밀번호·쿠키·세션·토큰이 없는지 확인한다.
4. 연결 화면에서 테스트 계정을 입력하고, 성공 전에 완료 표시가 나오지 않는지 확인한다.
5. Keychain 최초 승인 후 동기화를 두 번 실행한다. 두 번째 실행에서 비밀번호 재입력이나 반복 권한 팝업이 없어야 한다.
6. 로그아웃·세션 만료를 재현해 한 번의 명시적 재연결로 복구되는지 확인한다.

## Windows

1. Python과 Git이 없는 새 사용자 계정에서 `turtleneck.exe --version`과 `--help`를 실행한다.
2. SmartScreen 안내가 무서명 번들과 체크섬 확인 절차를 설명하는지 확인한다.
3. 보조 앱 `turtleneck-companion.exe --status`를 실행하고 민감값이 출력되지 않는지 확인한다.
4. Windows 보호 저장소에 연결 정보를 저장한 뒤 두 번째 동기화에서 입력을 반복하지 않는지 확인한다.
5. 동기화 중단·재시작과 큰 자료 하나의 재개를 확인한다.
6. 앱·스킬을 삭제할 때 로컬 자료와 인증정보의 보존/삭제 선택이 안내되는지 확인한다.

## 판정

각 항목은 `통과`, `실패`, `미실행` 중 하나로 기록한다. `미실행`은 성공으로 계산하지 않는다. 실패 시 운영체제 버전, 번들 버전, 단계 번호, 비밀값 없는 오류 문구만 Issue #4에 남긴다.
