# TLS 과제 제출 계약

과제 제출은 조회와 달리 학교 서버의 상태를 바꾸는 작업이다. 따라서 다음 순서를 지킨다.

1. 사용자가 지정한 과제 ID의 실제 TLS 화면을 연다.
2. 화면에서 제출 폼, 본문 입력 칸, 파일 선택기, 최종 제출 버튼을 읽는다. 양식이 없거나 주소가 학교 주소와 다르면 중단한다.
3. `--inspect` 단계에서는 제출하지 않고 가능한 입력 방식만 보여준다.
4. 실제 전송은 `--apply --confirm 제출`이 모두 있을 때만 수행한다. 파일 선택기 업로드와 답안 저장 뒤 최종 제출을 분리한다.
5. 제출 후 같은 과제 화면을 다시 읽어 `제출 완료` 또는 Moodle의 동등한 완료 문구를 확인한다. 확인되지 않으면 성공으로 말하지 않는다.

## 짧은 결과 양식

```md
### 과제 제출 확인
- 과목: 자료구조
- 과제: Ex05
- 상태: ✅ 제출 완료
- 제출 파일: `Ex05.java`
- [TLS에서 확인하기](https://tls.example/mod/assign/view.php?id=42)
```

실패·미확인일 때는 상태 아이콘만 `⚠️`로 바꾸고, 원인 한 줄만 덧붙인다. URL은 `sesskey`, 쿠키, 토큰이 제거된 확인 주소만 사용한다. 제출 폼의 hidden 값, 업로드 식별자, 원본 HTML은 사용자 답변·로그·AI 입력에 포함하지 않는다.

제출 성공 여부와 파일명 확인은 실제 TLS 화면의 문구를 기준으로 한다. 로컬 파일이 존재하거나 POST가 HTTP 200을 반환한 것만으로 제출 완료라고 단정하지 않는다.
