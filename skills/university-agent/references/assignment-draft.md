# 과제 초안 계약

과제물을 만들 때는 바로 작성하지 않는다. 먼저 TLS 과제 상세 화면, 해당 과목의 공지·개요, 사용자가 선택한 Notability 필기·완료 전사를 대조한다. 과제 상세 화면에만 있는 댓글·주의사항도 같은 원문 근거로 취급한다.

1. `python3 scripts/run_agent.py assignment-draft --course "과목명" --query "과제명"`으로 로컬 TLS 과제 상세·공지·개요와 세 가지 질문을 만든다. 내부적으로는 `features/assignment_draft.py`의 `prepare`를 사용한다.
2. 사용자에게 교수님이 수업·댓글에서 강조한 점, 제출 형식·분량·파일명·인용 규칙, 반드시 넣거나 뺄 내용을 한 번에 확인한다.
3. 호스트는 원문 `SOURCE`와 `userAnswers`를 분리해 `requirementChecks`와 `professorChecks`에 근거 위치·연속 인용을 남긴다. 자료에 없는 조건은 추측하지 않는다.
4. `validate`가 통과하고 `missingQuestions`가 비어 있을 때만 초안을 확정한다. 확인이 남아 있으면 짧은 확인 카드만 보여준다.
5. 결과는 Markdown으로 먼저 보여주고, 사용자가 고른 경우 DOCX 또는 HWPX로 내보낸다. 구형 HWP 바이너리를 만든 것처럼 말하지 않는다.

## 짧은 결과 양식

```md
### 과제 작성 전 확인
- 아직 초안을 확정하지 않았어요.
- 확인할 내용: 제출 파일 형식은 무엇인가요?
```

확정 결과에는 과목·과제·형식·교수님 강조점만 짧게 표시한다. 원문 HTML, 쿠키, 세션, 숨은 폼 값은 출력하지 않는다.

## 자료 도구가 없는 환경

- HWP/HWPX를 처리할 때 먼저 터틀넥에 포함된 HWPX/XML·DOCX 경로와 현재 설치된 변환기를 확인한다. 이미 호환되는 경로가 있으면 별도 스킬을 권하지 않는다.
- 호환되는 HWP 도구가 없을 때만 “추가 도구를 설치할까요?”라고 묻고, 사용자가 만든 터틀넥 호환 패키지를 먼저 제안한다. 대체 스킬이 이미 같은 기능을 제공하면 중복 설치를 권하지 않는다.
- Notability는 민감 자료이므로 목록 확인과 선택 노트 내용 확인을 각각 동의받는다. 현재 호스트에 호환되는 Notability 기능이 없을 때만 설치 여부를 묻고, 호환되는 기능이 있으면 그 기능을 그대로 사용한다.
- 설치 전에는 이름·출처·필요 권한·대체 가능 여부를 짧게 설명한다. 사용자 승인 없이 다운로드·설치하지 않는다.
