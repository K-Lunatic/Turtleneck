# 학교별 Moodle 모듈 기여 안내

터틀넥은 공통 Moodle 읽기 흐름과 학교별 확장을 분리한다.

## 모듈의 경계

- 표준 강좌·토픽·활동·일반 자료는 공통 제공자가 처리한다.
- 학교별 로그인, SSO, 강좌 목록, 동영상 뷰어, 파일 권한, 자율강좌는 별도 모듈로 둔다.
- 현재 건국대 TLS 전용 판단은 providers/moodle_kku.py와 providers/moodle_site.py에 둔다.
- 다른 학교에서는 KKU 주소를 추측하거나 호출하지 않는다.

## 다른 학교 연결 절차

1. 사용자가 로컬 보안 로그인 화면에서 학교 계정으로 직접 연결한다.
2. 첫 실행은 읽기 전용 마이그레이션 확인만 한다.
3. 강좌 목록, 강좌 화면, 활동 종류, 자료 보기·다운로드 응답, 권한 차이를 로컬 fixture와 요약으로 비교한다.
4. 에이전트는 실행 가능한 코드를 즉시 만들지 않고 학교 모듈 제안, fixture, 미지원 기능 목록을 만든다.
5. 사용자가 제안을 확인한 뒤에만 해당 프로필에 모듈을 설치·활성화한다.
6. 실제 사용 중 새 양식이 확인되면 기존 모듈의 fixture를 갱신하고, 변경 범위를 검토한 뒤 최적화한다.

## 사용자가 기여하는 방법

표준 Moodle 연결이 이미 동작한다면, 학교 계정으로 평소처럼 읽기 기능을 사용한 뒤 다음 명령으로
비밀값 없는 마이그레이션 리포트를 만들 수 있다.

```bash
python3 skills/university-agent/scripts/moodle_migration.py \
  --base-url https://lms.example.ac.kr \
  --account-alias 본계정 \
  --output ~/Downloads/turtleneck-moodle-migration.json
```

리포트에는 학교 호스트, 과목·활동 개수, 활동 유형, 요청량과 표준 모듈에서 벗어날 가능성이 있는 항목만
들어간다. 강좌명·강좌 ID·원문 HTML·원본 파일·비밀번호·쿠키·세션은 포함하지 않는다. 생성한 JSON을
[기능 제안 이슈](https://github.com/K-Lunatic/Turtleneck/issues)에 첨부하거나, 모듈 코드를 직접 기여할
때 함께 제출하면 유지 관리자가 학교별 모듈과 비밀값 없는 fixture로 검토한다.

기여가 반영되는 순서는 `리포트 확인 → 모듈 제안 → fixture·회귀 테스트 → 읽기 전용 활성화 →
트래픽 측정 후 최적화`다. 학교 담당자와 비공개로 협의해야 하는 경우에만 별도 연락을 사용하고,
공개 이슈에는 계정·서명 URL·원본 강의자료를 올리지 않는다.

## 보안 경계

- 비밀번호, 쿠키, 세션 값, CSRF 값, 업로드 식별자는 모듈·fixture·AI 입력에 저장하지 않는다.
- 관찰하지 않은 엔드포인트, 숨은 URL, 다른 호스트의 다운로드 주소는 생성하지 않는다.
- 자동 생성 모듈은 읽기 전용으로 시작하며, 제출·업로드·수정 기능은 별도 권한과 사용자 승인이 필요하다.
- 자동 모듈 생성은 로컬 파일을 실행하거나 설치하는 기능이 아니다. 항상 제안과 검증 단계를 거친다.

학교별 모듈을 기여할 때는 학교 이름, 실제 주소, 지원한 기능, 미지원 기능, 재현 가능한 비밀값 없는 fixture와 테스트를 함께 제출한다.

## Moodle Web Service 토큰

기존 학교 아이디·비밀번호 프로필은 유지하고, API 토큰은 별도 항목으로 저장한다.

```text
사이트 + 별칭
  ├─ 학교 로그인 비밀번호 → OS 보호 저장소
  └─ Moodle Web Service 토큰 → 별도 OS 보호 저장소 항목
```

토큰 연결은 사용자가 학교 관리자에게 허용받은 서비스 토큰을 보안 입력 화면에 직접 넣을 때만
활성화한다. 토큰은 `moodle-api-accounts*.json`에 평문으로 저장하지 않으며, API 호출은
`/webservice/rest/server.php`에 POST로만 보낸다. 토큰이 없거나 만료되면 기존 HTML Provider로
돌아가고, API 경로를 추측하거나 코스모스 앱 바이너리를 분석하지 않는다.

권장 학교 설정은 `moodle_mobile_app` 전체 권한을 그대로 재사용하는 것보다, 과목 목록·과목 내용·
변경 확인에 필요한 읽기 함수만 포함한 별도 외부 서비스다. 학교에서 토큰 발급 권한이나 Web Service를
열지 않으면 터틀넥은 기존 로그인 방식만 사용한다.
